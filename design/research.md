# PrintOps UI 优化 · oil-ui 研究笔记

日期：2026-10-24 · 分支：`ui/oil-redesign` · 方法：oil-ui SKILL.md 步骤 1

## 任务

存量项目 UI 优化（非改流程、非新功能）：可以重新决定偶然形成的视觉默认值，品牌资产保留；不引入框架、不加构建流程、不动业务逻辑。

## 认品类

**品类**：AI 辅助的印刷订单录入工作台（垂直行业工具，聊天式收集 + 结构化单据核对 + 报价比较 + 交接导出）。
**用户**：图文店 / 小印厂的接单员与店主，中文环境，桌面为主、移动端补位；一天内高频短会话使用。
**首屏主角**：进行中的对话与右侧订单草稿——内容优先的工作区，不是营销页。

## 拆标杆（真实画面存 `design/references/`）

### Linear（linear-home.png，2026-10 桌面首屏）

1. **深灰近黑底（#0f1011 级）+ 极细 1px 分隔线**：面板边界靠一条 hairline，不用阴影堆层级——为长时间盯屏减负。
2. **次级信息一律降饱和灰**，只有当前对象标题纯白：一眼锁定「我在看什么」。
3. **控件小而密**：侧栏行高约 28px，图标 16px，整栏密度高但靠严格对齐不乱。
4. **等宽字体承载「机器数据」**：`vehicle_state`、`DRV-8852` 这类标识符用 mono，与人话（描述文本）在字体层面分流。
5. **主操作唯一且克制**：右上单个胶囊 Sign up，正文内无第二个抢眼按钮。
6. **状态色极少出现**：黄星、状态点，其余全是灰阶——状态色出现即是信号。
7. **文案短句、零形容词**：「Render UI before sync…」直接说行为。
8. **产品截图即首屏主视觉**：真实工作界面放大做主角，证明工具本身。

### Vercel（vercel-home.png）

1. **纯白底 + 纯黑几何主视觉**：一个三角形承担全部情绪，无渐变弥散。
2. **排版即设计**：超大 grotesk 标题，字重对比（heavy 标题 / regular 正文）替代色彩对比。
3. **按钮只有黑/白两态**，圆角统一小值。

### Stripe（stripe-home.png）

1. **白底 + 大面积品牌渐变插画**：色彩只出现在一个主视觉区，控件区保持素净。
2. **数字与代码感**：GDP 计数器用 mono，工程可信感。
3. **中文排版行高宽松**（约 1.7），长行不压迫。

### 留什么、换什么（对照 PrintOps）

- **留**（理由同样成立）：状态色克制出现；mono 用于单号/尺寸/克重等「机器数据」；主操作唯一；真实内容做主角。
- **换**（理由不成立）：Linear 的深色底——PrintOps 用户场景是白天门店接单 + 打印交接单（纸张输出），暖纸底有业务隐喻且高对比主题已覆盖深色需求；Vercel 的极简留白——订单录入是高密度表单任务，疏排版会拉长滚动路径。

## 调性（五刻度，各方向共用）

依据：行业工具、高频录入、印刷行业审美、本地严肃数据。

| 刻度 | 取值 | 依据 |
| --- | --- | --- |
| 能量 | 安静 | 接单是核对型任务，不娱乐 |
| 完成度 | 精致 | 单据要导出给供应商，观感即信任 |
| 密度 | 中密偏密 | 桌面三栏工作台，字段多 |
| 分量 | 中 | 不做粗野主义，也不做飘浮卡片 |
| 严肃度 | 庄重 | 报价与交接是商业文档 |

## 品类默认配色（各方向共同回避的「顺手色」）

- AI/开发者工具默认：黑底 + 紫蓝弥散光晕 + 胶囊按钮（Linear/Vercel 底子）。→ 三个方向都不以紫蓝为主色。
- 国内后台默认：灰底白卡片 + 蓝色主按钮（Ant Design 底子）。→ 不用灰底白卡 + 默认蓝。

## 现状盘点（基线截图存 `design/baseline/`）

**令牌层**（`styles.css:1-90`，`:root`）：暖纸 4 阶、油墨 4 阶、分隔线 3 阶、品牌红 `--red*`（#a34a3e 族）、黄铜/金、状态绿/信息/警告；间距 1–8、圆角 xs–pill、字号 xs–xl、两种阴影（硬偏移/软）、焦点环。第二主题 `html[data-theme="high-contrast"]`（92–176 行）整体覆盖。字体：标题 Georgia/宋体衬线，正文 Avenir Next/PingFang/雅黑。

**布局**：三栏 CSS Grid 工作区 + 两个可拖拽分隔条 + 折叠开关；1050/700/420px 断点；`journey.js` 在加载时把部分面板 DOM 重挂载到不同旅程阶段——结构不可随意重排。

**已确认的问题**（对照 02/04/05 基线图）：

1. 左栏标题截断（「当前…」「订单 AD…」）——密而不齐。
2. 层级只靠 1px 描边，卡片/分组缺少第二层级手段，观感平。
3. 右栏「已填写/未设置/待补充」三种状态区分弱：绿底/灰字/红叹号各自为政。
4. 核对页行距过疏（每字段下挂「依据」「编辑或清空」两行链接），与左栏高密度形成失衡节奏。
5. 次级文字（时间戳、「已保存到本机」）对比度偏低。
6. 空状态（首用图 01）只有一行提示，浪费首屏引导时机。

**必须保留**：三栏骨架与拖拽分隔条、journey.js 重挂载逻辑、高对比主题、无障碍设施（aria/焦点环/reduced-motion）、server.py 静态白名单、全部现有文案与交互习惯。
