## 2. 目标与不变约束

目标是恢复原版直接表达的体验，把改进集中在左右侧栏的内容层级、统一操作与拖动可靠性。
首次进入只给一个清楚的输入入口，不要求先选用途、品类或工作阶段。
北极星继续采用原定义：8 名未参与开发的用户，至少 7 名在 10 分钟内独立完成合格交接。
主任务仍为名片 3 人、单页 3 人、标准宣传册 2 人；失败、放弃和超时不得移出分母。
合格完成须包含当前版本确认、实际打开导出文件及独立内容复核，不能只统计点击下载。
尺寸使用 mm，纸张克重使用 g/m²；尺寸语义、数量单位及产品归属不得因界面精简而丢失。
默认 SQLite 和可替换 OrderStore 保留；布局偏好不得改变订单存储或审计策略。
示例估算继续展示来源、版本、适用范围及未包含项，不能展示为供应商正式报价。
供应商中立、真实连接未授权、本地确认不是发送、导出不是供应商接收的边界保持不变。
正式发布仍要求至少 20 例真实脱敏语料、字段准确率至少 95%，以及既有发布清单的其他要求。
编写本文时真实脱敏语料仍为 0，正式发布门禁继续阻断；合成测试和 8 人走查不能替代它。

## 4. 唯一方向：原版中央骨架，打磨左右侧栏

```text
左侧历史栏                  中央保持 GitHub 原版骨架           右侧订单检查器
新建 / 历史                 section-title + 原有侧栏开关       默认关闭
                            chat-feed + 动态追问 chips         摘要 → 待处理 → 参数/文件
底部：设置                  composer（唯一输入/上传/发送）      方案/交接按需展开查看
```

左栏只承载新建、历史和设置；当前阶段、运行记录、产品目录不再占据左栏首屏。
中央恢复原版四段结构，常规流程始终保留对话与唯一输入；只调整与侧栏配合所需的宽度、滚动和状态提示。
空状态保留一句简短引导；输入示例如保留则放帮助内，不再向中央加卡片、选项组或新的操作层。
订单按钮可显示待处理数量，不能把字段完整率包装为生产就绪或已发送状态。
右侧检查器按用户操作打开，依次显示当前订单/产品摘要、待处理项、参数/文件，再提供方案与交接入口。
这些内容使用清楚的小标题和必要折叠，不把右栏堆成一组新 tabs；生产字段只保留一个编辑入口。
收到普通回复或切换方案状态时，不自动打开、关闭检查器或把用户带离对话。
比较与文档需要宽空间：从检查器明确点击“展开比较”或“展开交接单”，进入右栏内容的展开阅读模式。
展开阅读可按需占用中央及右侧可用工作区，不能把差异表和完整交接单硬塞进窄侧栏；它不是新的中央默认架构。
这里“永久对话”指对话实例与状态保留；显式展开期间允许暂时隐藏其视觉呈现，不卸载或清空它。
全宽视图提供明显的“返回对话”，返回后恢复输入草稿、编辑草稿、滚动位置和触发入口焦点。
全宽视图不创建第二个聊天输入框，也不通过复制 DOM 形成两套订单编辑器。

## 6. 展示状态与业务状态分离

建立单一布局状态：左右栏开关、栏宽、当前检查器内容、全宽内容、返回位置；它不写订单 revision。
短期可保留 `view("compare"/"review")` 为兼容入口，内部改为打开检查器或全宽内容，不再切掉聊天阶段。
明确移除 `journey.init()` 对旧容器的隐式搬运，避免新 HTML 被运行时重新搬回原布局。
每个业务组件只保留一个实例；搬迁真实节点并保留监听，不能复制带相同 ID 的组件。
将 `renderDraft()` 的状态/按钮可用性计算与旧字段 DOM 渲染拆开，删除旧编辑器时保留业务计算。
`review.fields`、`review.issues`、`handoffDocument` 继续作为展示来源，前端不得另造生产校验结论。
保留 revision、itemId、请求视图序号及过期响应拦截；打开面板不隐式更换产品或触发业务写入。
保留候选确认/拒绝、409 差异核对、确认动作禁止重放、按订单隔离的未知提交恢复。
保留编辑草稿、输入草稿、归档只读、修改后确认失效以及导出时重新校验当前版本。
错误恢复必须持续可访问；不能随检查器关闭消失，也不能恢复成只弹瞬时 toast。
多产品作用对象放在输入区附近；上传、编辑、方案选择继续明确显示所属产品。

## 7. 左右栏统一交互与样式

两侧使用同一套 surface、header、边界、间距、滚动与收起规范，宽度可因用途不同。
左栏承担导航，右栏承担检查；不能因此使用两套不一致的标题高度、关闭按钮或焦点规则。
以下数值是实施起值，均待走查验证，不是已验证的最佳尺寸。

| Token/规则 | 建议起值 | 使用方式 |
| --- | --- | --- |
| 栏标题高度 | 56 CSS px | 与本轮布局示意一致；两侧标题对齐，滚动时标题留在各自容器顶部。 |
| 栏内容间距 | 内边距 16px，组间 16px，项间 8px | 通过共享 token 控制，不逐组件补偏移。 |
| 栏表面与边界 | 同一中性底色、1px 边界、相同状态色 | 品牌色用于必要强调，降低装饰密度。 |
| 左栏宽度 | 默认 240px，范围 200–320px | 保证历史标题和新建入口可读。 |
| 右栏宽度 | 默认 360px，范围 320–480px | 用于检查摘要，不承担宽文档阅读。 |
| 中央最小宽度 | 480 CSS px | 动态宽度约束的建议起值；不足时进入抽屉模式。 |
| 对话内容宽度 | 最大 800px | 容器更宽时居中，窄时随可用宽度收缩。 |
| 分隔线命中区 | 8px，另保留可聚焦的收起按钮 | 视觉边界可细，鼠标和键盘入口都明确。 |

各栏只保留一个主内容滚动容器，避免外栏、卡片与内容同时嵌套滚动。
栏之间由分隔线绘制单条边界，取消分隔线双侧边框与栏自身边框的重复叠加。
栏内分组用留白、小标题和细分隔线区分；历史用列表行、参数用字段行，不再给每层容器套底色、边框和阴影。
收起操作保留内容位置；再次展开恢复位置，标题开关使用一致图标语义及 `aria-expanded`。
按钮触发的展开/收起可共用约 160ms 的缓出效果，开启 reduced-motion 时关闭；拖动宽度不使用过渡或惯性。
布局存储增加版本，迁移旧 `printops_layout`；新规则默认关闭订单栏，不能被旧缺省值悄悄覆盖。
删除 compare/review 的 300px `!important` 特例，所有显示模式共用同一有效宽度来源。

## 8. 统一分隔线控制器

左右分隔线共用一个 pointer controller，通过方向参数区别左栏和右栏。
拖动遵循指针 1:1 位移，仅在合法宽度边界截断；不加惯性、回弹或宽度过渡动画。
按下时仅接受主指针和主按钮，记录 pointerId、起始 clientX、起始栏宽和容器约束，然后设置 pointer capture。
使用起点增量：`deltaX = currentX - startX`；左栏 `startWidth + deltaX`，右栏 `startWidth - deltaX`。
不得用“当前指针到容器边缘的距离”替代起始宽度，否则点击分隔线不同位置会造成起拖跳变。
pointermove 只保存最后一个样本；若已有待执行 rAF，不再安排第二个。
每个 rAF 消费最后样本一次并写入一次有效栏宽，避免每个 pointermove 反复读写布局。
pointerup 必须先使用最后坐标 flush 最终宽度，再取消待执行帧、释放 capture、清理监听并保存布局。
pointercancel 与 lostpointercapture 走同一幂等清理路径，取消待执行帧并保留最后已显示的合法宽度。
所有结束路径都移除拖动类、光标和禁止选择状态；重入清理不能重复保存或残留监听。
拖动中组件销毁、窗口失焦及模式切换也调用清理，不能遗留下一次 pointer 事件的闭包。
容器 resize 时重新计算约束，避免在每个 pointermove 中读取容器几何。
有效最大栏宽取配置上限与“容器宽度 − 另一可见栏 − 可见分隔线 − 中央最小宽度”的较小值。
区分保存的偏好宽度与本次容器下的有效宽度：空间减少时先联合约束两栏，空间恢复时恢复偏好，不能把临时压缩写回用户偏好。
若两栏最小宽度加中央 480px 已无法容纳，切换为抽屉；不制造负宽度或压缩到不可操作。
ArrowRight 表示分隔线向右运动，ArrowLeft 表示向左运动，两侧遵循同一空间方向。
建议每次键盘移动 16px：左栏按运动增量加宽，右栏按运动增量减宽，修复当前右侧反向行为。
Home/End 可定位本栏当前有效最小/最大宽度；双击恢复默认值后仍须通过容器约束。
分隔线提供 `role="separator"`、`tabindex="0"`、`aria-orientation="vertical"` 和 `aria-controls`。
`aria-valuemin/max/now` 取当前有效栏宽范围与值，`aria-valuetext` 明确“左栏/订单栏，N 像素”。
鼠标、键盘、重置、容器变化均复用同一 clamp/apply 路径并同步 ARIA；隐藏分隔线不可获得焦点。
实施后再记录 resize 的事件、帧写入与视觉结果，不预先承诺 FPS 或毫秒级改善。
可自动验收的几何标准：非边界截断时，下一次绘制后分隔线位移与指针位移之差不超过 1 CSS px；松手后无延迟补动。

## 9. 窄屏与焦点规则

窄屏左右栏成为两个互斥 drawer：打开一个先关闭另一个，共用遮罩与关闭语义。
drawer 打开时背景不可交互，焦点限制在当前 drawer；Esc 关闭并返回实际触发按钮。
关闭后保留各自滚动位置；跨断点切换时释放 pointer capture，重新同步隐藏状态和焦点。
全宽比较/交接同样提供返回入口；从其中定位字段时先打开正确产品与分组，再聚焦字段。
手机只保留一个输入框，软键盘出现时输入框及发送按钮不能被遮挡或挤出可视范围。
统一使用动态视口、安全区与必要的 visualViewport 适配，删除互相覆盖的固定高度补丁。
保留 44px 高频触控目标、可见焦点及对比度要求；200% 缩放时允许切换抽屉布局。
390px 桌面浏览器视口只算窄屏回归；真实手机键盘、系统滚动和触摸必须另外记录设备验收。
