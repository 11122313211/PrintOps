# 首次用户走查包：10 分钟合格交接

版本：2026-10-15 / v1。状态：**任务与评分设计已提供；尚未招募、执行或得到真人结果。** 本文件只包含人工编写的测试任务，不是真实客户订单，不得加入真实语料发布库。执行前锁定工作区版本、环境及本文版本；中途改任务或改产品后另起一轮，不拼接成同一轮结果。

## 1. 测什么，怎样算完成

目标：首次使用的非印刷专业用户，在 10 分钟内独立完成规格正确、关键参数已核对、依据可追溯的本地交接单。

- **开始**：本地服务已就绪，用户提交首条有效需求时计时。启动安装另表测量；阅读任务卡所需时间另记。
- **结束**：当前版本通过必要校验、关键生产参数已核对，用户明确确认；导出后实际打开文件，内容与该已确认版本一致。任务内澄清、等待、修改、确认和导出全部计时。
- **合格**：独立复核者按第 5 节检查导出内容、确认记录与任务约束；缺少证据不能记为通过。时间内达到结束事件但内容复核失败，仍是不合格任务。
- **独立**：主持人未提示按钮、操作顺序、应选择哪个方案，也未代填参数。用户主动询问任务背景时，只能读任务卡中预先固定的事实；这不算操作帮助。主持人提供操作帮助时记录原话，主任务记为未独立完成，可以继续观察。
- **不等同于完成**：字段填满、生成草稿、点击下载、浏览器打印窗口出现，以及供应商未知信息被隐藏。无文件时必须写清“文件待交付 / 未做文件检查”，不能写成可直接生产。

主指标：**10 分钟合格交接完成率 = 600 秒内独立完成且通过内容复核的主任务数 / 所有已开始的主任务数**。8 个任务全执行后分母为 8；失败、放弃和超时不得删除。招募不足时只报已开始数量和阶段结果，不宣称达成 7/8。超过 600 秒可以继续观察至用户主动停止或主持人按预定 900 秒结束，主指标仍记超时。

本轮形成性目标：至少 7/8 个主任务合格完成；关键尺寸错误、数量错误、产品串项、过期确认沿用均为 0；8 人均能区分示例估算与供应商报价，并知道订单尚未发送。小样本用于发现问题，不证明总体成功率或各品类稳定成功率。真实订单至少 20 例、准确率 ≥95% 的发布门槛另行执行。

## 4. 主持流程与理解题

1. 确认参与者首次使用、环境就绪和记录权限。说明“我们在测试产品，没有要求你一次做对”，不演示界面。
2. 阅读指定任务，记录阅读时间；从第一条有效需求提交开始计时。只按业务信息卡回答背景问题，记录澄清次数、操作帮助和错误。
3. 用户核对、确认、导出并打开文件后停表；保存原始导出及对应版本/确认记录的证据。不要在停表前帮忙修正订单。
4. 不先解释概念，依次询问并记录原话：
   - “这里的金额是什么，能直接当作印刷厂已经给出的报价吗？”
   - “现在谁已经收到这张订单？还需要你做什么？”
   - “这份资料中的文件检查完成了吗？能直接生产吗？”
   - “如果你现在把数量改掉，刚才的估算和确认还能直接用吗？”
5. 内容复核者按评分表检查，不观看一个“修好后的替代结果”来覆盖首次结果。可以允许参与者在单独的补充观察中修正，另记修正耗时。

金额题通过：明确为本地示例估算、需供应商另行报价；发送题通过：明确尚未发送、需后续人工交接；文件题通过：本主任务文件待交付且未完成检查；修改题通过：需重新核对相关方案/估算和确认。只答“知道了”不算有证据的理解。
