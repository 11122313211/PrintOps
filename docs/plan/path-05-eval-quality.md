# 路径五：评测体系与 NLU 质量持续提升（path-05-eval-quality）

> 优先级 P1　目标版本：持续（首期 3 人日随 v0.12.0）　依赖：v0.11.0 真实语料机制（已就绪）

## 1. 现状与问题

### 1.1 当前资产

- 合成语料 111 例（`tests/evaluate_agent.py` 内嵌），按 7 个标签分组（基础 21 / 尺寸格式 32 / 数量表达 24 / 修改 10 / 否定 8 / 歧义 8 / 多产品 8），字段准确率 100%、可完成用例完整率 100%、平均达标轮数 1.22；
- 真实语料机制：`tests/eval_cases_real.json`（≥20 例启用 ≥95% 硬门槛）、`tools/annotate_case.py` 标注辅助、四态判定（pending/record/pass/fail）；
- `run_suite(cases)` 已参数化，可对任意语料运行。

### 1.2 问题

1. **循环论证风险仍在**：合成语料由实现规则的人编写，100% 准确率不构成外部证据——这正是 1.0 门槛要求真实语料的原因，但真实语料目前为 0；
2. **坏例没有回流通道**：真实使用中发现的错误理解，没有"复现 → 修复 → 固化为用例"的固定流程，同类错误可能复发；
3. **双轨一致性无断言**：规则模式与 LLM 模式对同一句话的行为差异从未被系统性比较，切模型/换提示词的影响不可知；
4. **评测只有汇总数字**：没有随版本的趋势记录，无法回答"这个月感知质量是变好还是变坏"；
5. **品类覆盖不均**：画册/名片/折页类用例多，纸杯/喷画/PVC 卡等长尾品类的专属参数用例薄。

## 2. 目标与非目标

### 2.1 目标

1. 真实语料在 v1.0 发布前达到 ≥20 例，v1.1 前达到 50 例，且字段准确率 ≥95%；
2. 建立**坏例回流流程**：任何真实使用中的理解错误都能在 30 分钟内变成一条固化用例；
3. 建立**双轨一致性断言**：同一语料在规则模式与（可选）LLM 模式下的字段结果差异可度量、可回归；
4. 评测报告带**版本趋势**：每次发布记录关键字段准确率/完整率/轮数快照，形成可查的历史序列；
5. 长尾品类用例补齐：每个支持品类至少 2 条基础用例。

### 2.2 非目标

- 不做线上 A/B 或远程指标回传（本地工具，无遥测；这是产品原则不是技术限制）；
- 不做自动语料生成（LLM 生成用例的标注可靠性不足，宁可慢）。

## 3. 方案设计

### 3.1 真实语料征集与回流流程

**来源优先级**：走查记录中的真实输入（门槛 7 的副产品）> 同事/朋友的实际印刷需求 > 客服记录/聊天存档。

**回流流程（坏例 → 固化用例）**：

1. 发现错误理解（如"条幅"没被识别）→ 在 `tests/eval_cases_real.json` 追加一条：原话进 `turns`，**正确答案**进 `expected`（以印刷行业常识标注，不是以当前系统行为标注）；
2. 运行评测确认该例失败（失败是预期）；
3. 修复规则或知识（`nlu.py` / `product_knowledge.py`），评测转绿；
4. CHANGELOG 记录"感知修复：原话 → 修复方式"，该用例从此成为永久回归。

**防污染约定**：expected 永远反映"应该理解成什么"，绝不为了变绿而改标注；确属标注错误的，在用例 `"name"` 后缀 `（标注修正 YYYYMMDD）` 并在 CHANGELOG 说明。

### 3.2 双轨一致性断言（nightly）

新增 `tests/compare_modes.py`（不进默认 unittest 发现，nightly/手动运行）：

- 对全部语料分别以"规则模式"与"LLM 模式（fake planner，回放预录响应）"运行 `run_suite`；
- 输出字段级差异报告：同一用例同一字段两轨结果不同的清单；
- 断言规则：真实 LLM 需要网络与凭据，CI 不可依赖——用**预录响应回放**（把一次真实 LLM 会话的 planner 返回录成 JSON fixture）保证可重复；每次更换提示词或模型时重录 fixture 并人工审核差异报告；
- 产出：`docs/eval/consistency-YYYYMMDD.md`（人工审阅后归档）。

### 3.3 评测趋势快照

`evaluate_agent.py` 新增 `--record`：把当前报告的汇总指标（准确率/完整率/平均轮数/各标签准确率/用例数/知识版本号）追加写入 `docs/eval/history.jsonl`（一行一条，含 git 短哈希与 VERSION）。发布流程（RELEASE_CHECKLIST）加入"评测 --record"一步。`--trend` 选项输出最近 10 条的对比表，直观回答"变好还是变坏"。

### 3.4 长尾品类用例补齐清单（首期）

| 品类 | 现有用例量级 | 补充目标（合成语料内新增） |
| --- | --- | --- |
| 纸杯 | ≈1 | +2：单/双 PE、容量表达（9 盎司/250ml）、千只起订 |
| 喷画 | ≈1 | +2：平米计价话术、目数/精度、安装方式 |
| PVC 卡 | ≈1 | +2：厚度（0.38/0.76mm）、智能卡芯片、磁条 |
| 联单 | 少 | +2：联数、二联三联、无碳复写 |
| 手提袋 | 少 | +2：覆膜、绳色、尺寸与提袋方向 |
| 标签（异形） | 少 | +2：刀模尺寸语义、排标数量换算 |

每条新用例遵循既有格式（name 唯一、tag 归入对应分组、expected 只标原话明确提到的字段）。

## 11. 指标口径表（评测数字的精确定义，避免口径漂移）

| 指标 | 定义 | 归一化 | 门禁 |
| --- | --- | --- | --- |
| 字段准确率 | Σ(字段匹配) / Σ(期望字段)，字段匹配 = `_normal(实际) == _normal(期望)` | 空白去除、＊/*→×、小写化、NFKC | 合成 100%（既有基线）；真实 ≥95% |
| 可完成用例完整率 | `EXPECT_COMPLETE` 标记的用例中，补全轮次后 `missingFields` 为空的比例 | — | 合成 100%；真实 ≥80% |
| 平均达标轮数 | 首次 `missingFields` 为空的轮次（含补全轮），未达标不计入均值 | — | 仅记录，趋势观察 |
| 供应商外部字段 | `order.*.external*` 一律不进入字段统计 | — | 路径 3 落地时在 evaluate_agent 显式排除 |
| 通过用例 | fieldAccuracy == 100 的用例数 | — | 报告展示 |

`history.jsonl` 行示例：

```json

 "synthetic": {"cases": 123, "fieldAccuracy": 100, "completionRate": 100, "avgTurns": 1.21},
 "real": {"cases": 24, "fieldAccuracy": 95.8, "completionRate": 87.5, "verdict": "pass"}}
```

## 12. 双轨一致性报告结构（consistency-YYYYMMDD.md）

1. 元信息：fixture 录制日期、模型名、提示词版本、语料版本；
2. 总体差异率：字段级不一致数 / 总字段数（分轨分用例矩阵）；
3. 差异清单（逐条）：用例名、字段、规则结果、LLM 结果、人工裁定（LLM 更优 / 规则更优 / 等价 / 待办）；
4. 行动项：需修规则的（转坏例回流）、需修提示词的、需补语料的；
5. 结论：本次模型/提示词变更是否可合入。

首期验收：报告能回答"切换提示词后哪些用例行为变了"，且每条差异有人工裁定列。

## 13. 标注质检与坏例归因分类学

真实语料的可信度取决于标注质量。一条错误标注进入语料库后，每次回归都要么冤枉
规则（假失败）、要么掩盖缺陷（假通过），且排查成本远高于入库成本。本节定义
标注的质控流程与坏例的归因体系，二者是评测体系长期可信的两根支柱。

### 13.1 标注质检流程（双人标注 + 仲裁）

1. **独立标注**：每条真实用例由标注人 A 先用 `tools/annotate_case.py` 生成草稿，
   逐字段核对后形成"标注一"；标注人 B 在**不看标注一**的情况下独立完成同样流程，
   形成"标注二"。
2. **自动比对**：`tools/annotate_case.py --diff a.json b.json`（新增子任务，标准库
   实现）输出两份标注的字段级差异清单：仅一方存在的字段、值不同的字段、路径不同的
   字段。
3. **仲裁**：差异字段由 A/B 对照原始话术讨论定性——原话确实有歧义（改用例并在
   `notes` 字段记录歧义点）、一方漏看（修正）、双方都错（讨论后共同修正）。无第二
   标注人时（单兵阶段），允许"隔日自审"替代：标注完成后至少隔一个工作日再核对一遍，
   并在用例 `notes` 里记录 `self-reviewed: 日期`。
4. **入库标记**：完成质检的用例加 `"qa": "dual" | "self" | "raw"` 字段。评测报告
   分组统计时按 qa 分层——`raw` 用例不参与硬门禁计算（待质检），避免低质标注污染
   门槛数字；当 raw 占比 >30% 时，周报必须给出质检排期。

### 13.2 坏例归因分类学（四类 + 复合）

评测失败（`expected` 与实际不符）必须先归因再动手，禁止"哪里红了修哪里"：

| 归因码 | 含义 | 典型特征 | 处理路径 |
| --- | --- | --- | --- |
| R（规则缺陷） | 确定性规则确实没覆盖该说法 | 同类说法的其他用例也红；手工复现稳定 | 转坏例回流：新增/修正规则 + 回归测试，规则修复后该用例转绿 |
| A（标注缺陷） | expected 与原话本意不符 | 单用例红；人工复读原话后确认标注错 | 修正标注并在 notes 记录修正原因与日期；不改任何产品代码 |
| K（知识缺陷） | product_knowledge 缺品类参数/风险规则 | 字段抽取正确但校验/推荐环节提示缺失 | 补知识条目并递增 knowledge version，契约测试同步 |
| C（口径缺陷） | 归一化比较规则本身不合理 | 实际值语义等价但 `_normal()` 判不等 | 修 `_normal()` 或字段路径口径，补等价类单测；须在周报中说明 |
| R+K 复合 | 规则与知识同时缺 | 跨两个环节的红 | 拆成两条独立坏例分别跟踪 |

归因写入 `data/eval/badcase-log.json`（追加式）：`{用例名, 归因码, 判定人, 日期,
处理任务卡, 状态}`。归因分布是路径健康度的领先指标——R 占比持续上升说明产品在
长尾说法上欠账，A 占比上升说明标注流程有问题，C 占比上升说明归一化口径在漂移。

### 13.3 双轨一致性断言的判定细则（补充 §3.2）

1. **字段级判定优先于文本级**：reply 文本允许自由发挥，patch/工具意图必须逐字段
   一致（经 `_normal()` 归一）；双方都为空视为一致。
2. **置信度联动**：规则轨对同一字段给出 `confidence < 0.75` 而 LLM 轨给出高置信
   补丁时，不算"不一致"，算"待人工裁定"——这正是低置信度机制设计的观察点，进
   裁定列而不是差异列。
3. **降级策略**：nightly 无可用模型时（未配置/厂商故障），报告输出 `skipped` 并
   保留上次成功快照；连续 5 次 skipped 后在周报标记"双轨断言失明"，作为提示词
   变更的额外审批条件（须人工跑一次全量）。
4. **变更留痕**：一致性报告引用的提示词版本来自 `llm_adapter` 的 `PROMPT_VERSION`
   常量（新增，随 §3.2 任务卡）——没有版本号的提示词变更不允许合入。

### 13.4 验收

- 双人标注流程在同批 ≥10 例上演练一次，diff 工具输出与人工比对一致；
- 坏例日志四种归因码各有一条演练记录，周报能按归因码出分布；
- 双轨断言在 fake SSE 服务器（路径 1 产出）上能稳定生成报告，skip 降级路径有测试。
