# 附录 D：度量与可观测性体系

> 隶属：《PrintOps 后续完善开发计划书》总纲第五节"横切关注点"的落地细节。
> 适用范围：v0.12.0 起的所有版本。度量不是事后补的报表，而是与测试门禁同级的
> 发布基础设施——没有度量的优化路径无法证明自己有效。
> 依赖：路径 1（run event 已结构化）、路径 4（存储有界）、路径 5（评测快照）。

## 1. 为什么要单独建度量体系

当前项目的"度量"散落在三处：评测脚本的 stdout（准确率/完整率）、run events（会话
内决策轨迹）、服务端 LOGGER（请求路径）。三者互不联通，回答不了管理层与开发者
最常问的四类问题：

1. **北极星问题**：新用户从第一句话到"可生成完整订单"平均花了几轮、几分钟？
2. **质量问题**：本周哪些字段/品类的识别在退化？坏例集中在哪个环节（感知/校验/推荐）？
3. **性能问题**：首字反馈、单帧渲染面板数、启动时间是否在预算内（总纲 §5.1）？
4. **规模问题**：会话数、消息数、SQLite 体积的增长曲线是什么形态（路径 4 清理策略的依据）？

本附录定义一套与零依赖约束兼容的最小度量体系：**本地 JSONL 事件日志 + 每周快照
+ 趋势对比**，不引入任何指标后端。

## 2. 北极星指标树

```
北极星：模糊需求 → 完整可交接订单的转化效率
├── A. 转化质量（评测离线度量）
│   ├── A1 真实语料字段准确率（硬门禁 ≥95%，≥20 例）
│   ├── A2 可完成用例完整率（≥80%）
│   └── A3 坏例回归率（上周坏例本周复发数 = 0）
├── B. 交互效率（会话日志在线度量）
│   ├── B1 平均澄清轮数（第一句 → missingFields 清空）
│   ├── B2 平均达成时长（首条消息 → 可 generate）
│   └── B3 人工修正率（用户 patch 与 agent 推断冲突次数 / 轮数）
├── C. 系统性能（性能预算，超预算即发布阻碍）
│   ├── C1 首字反馈延迟（LLM 模式 <1s；规则模式 <50ms）
│   ├── C2 单帧重绘面板数（≤3，路径 2 验收）
│   ├── C3 启动到可交互（<2s，路径 8 验收）
│   └── C4 评测套件总耗时（CI <30s，超时即拆分）
└── D. 健康度（运行时事件度量）
    ├── D1 规则回退触发率（LLM 失败回退次数 / LLM 调用次数）
    ├── D2 损坏会话恢复次数（data/corrupted/ 新增文件数）
    └── D3 500 错误率（按 requestId 统计）
```

口径原则：每个指标必须有唯一计算入口（一个函数或一个脚本参数），禁止在文档里
出现第二种算法。A 类以 `evaluate_agent.py --record` 的快照为唯一事实源；B/D 类
以 JSONL 事件日志为唯一事实源；C 类以测试断言为唯一事实源。

## 3. 本地事件日志（JSONL）设计

### 3.1 文件与格式

- 位置：`data/metrics/events-YYYYMMDD.jsonl`（按日滚动，加入 .gitignore）；
- 每行一个 JSON 对象，字段固定：`ts`（ISO 时间）、`type`（事件类型）、`sid`（会话
  id，可脱敏为前 6 位）、`data`（事件负载）；
- 写入方式：追加写 + 立即 flush；单日文件超过 5MB 时只保留头部采样（每 10 条取 1）
  ——度量日志本身也必须有界，否则违背路径 4 的存储治理。

### 3.2 首批事件类型（v0.12.0 落地 8 种）

| type | 触发点 | 负载要点 | 服务的指标 |
| --- | --- | --- | --- |
| session_start | Agent 创建 | is_new（是否复用旧会话） | 规模曲线 |
| chat_round | 每次 /api/chat 完成 | duration_ms、mode（rule/llm）、streamed、turns_since_ready | C1、B1 |
| ready_reached | missingFields 首次清空 | round_index、elapsed_ms | B1、B2 |
| generate | generate() 返回 | ok、blocked_reason | 转化漏斗 |
| llm_fallback | planner 返回 None | last_error 类别（超时/格式/连接） | D1 |
| render_batch | render() 完成一批 | panels_updated、duration_ms | C2 |
| corrupted_recovered | Memory._quarantine | sid 前缀、错误类别 | D2 |
| api_error | error_response 非 4xx | code、path | D3 |

### 3.3 采集纪律（防止度量反噬产品）

1. 事件写入失败必须静默吞掉（OSError/磁盘满不影响主流程），度量永远低于功能优先级；
2. 日志中禁止出现订单字段明文（只记字段名与长度，不记值）——与"日志不落 Key"同一纪律；
3. 每种事件的 schema 变更必须递增 `metricsSchema`（写入每行 `v` 字段），解析端按版本分派；
4. `data/metrics/` 在"导出/交接"功能中默认排除，避免误发。

## 4. 周快照与趋势对比

### 4.1 快照命令

```bash
PYTHONPATH=. python3 tests/evaluate_agent.py --record       # 已有：评测快照
python tools/metrics_report.py --week                        # 新增：聚合本周 JSONL
python tools/metrics_report.py --compare <上周快照.json>      # 新增：周环比
```

`tools/metrics_report.py`（路径 5 任务卡新增 S5-09）只依赖标准库：读 JSONL → 聚合
出 §2 指标树全部叶子值 → 输出 Markdown 报告与 JSON 快照。快照存
`data/metrics/snapshots/week-YYYYWW.json`。

### 4.2 周报结构（固定九段）

1. 指标树叶子值总表（本周 / 上周 / 环比）；
2. 越预算项标红（C 类任何一项超预算即列发布阻碍）；
3. 坏例Top3（按影响面排序，附归因类别——见路径 5 §13）；
4. D1 规则回退率异常说明（>10% 需要给结论：厂商故障 or 提示词回归）；
5. 会话规模曲线与存储水位（SQLite 体积、events 体积）；
6. 走查/真实语料新增数（门槛 4 进度）；
7. 本周任务卡完成与偏差（对照总纲第七节）；
8. 下周计划与风险升级建议；
9. 附录：原始 JSON 快照路径。

### 4.3 趋势门禁

- 真实语料准确率周环比下降 >2 个百分点 → 升级为活跃风险（总纲 §5.2 已约定）；
- C1/C2/C3 任一连续两周超预算 → 对应路径任务卡强制回炉，不接受"下版本再说"；
- 快照连续缺测两周 → 视为度量体系回归，记入技术债务登记册（附录 B）。

## 5. 与现有资产的接线（不重复造轮子）

| 现有资产 | 复用方式 |
| --- | --- |
| agent.py run events（结构化决策轨迹） | `ready_reached`、`llm_fallback` 事件直接从 `_event()` 出口旁路写入，不新增埋点点位 |
| evaluate_agent.py --record | A 类指标唯一来源；metrics_report 只读快照不重算 |
| server.py LOGGER | 只保留请求路径日志；结构化数据一律走 JSONL，避免双写 |
| Playwright 冒烟（路径 2） | C2/C3 由冒烟断言直接输出，作为门禁数字而非手测估计 |

## 6. 实施顺序与验收

1. **阶段一（S5-09a，0.5 天）**：JSONL 写入器 + 8 种事件埋点 + 滚动与采样；验收：所有事件有 schema 测试、写失败不影响主流程（注入 OSError 的单测）；
2. **阶段二（S5-09b，0.5 天）**：metrics_report.py 聚合与周报生成；验收：对固定 fixture 事件流输出的报告逐字段断言；
3. **阶段三（S5-09c，0.5 天）**：--compare 周环比与越预算标红；验收：构造"准确率下降 3 个百分点"的夹具，报告与退出码符合 §4.3 门禁；
4. **阶段四（随路径 2）**：render_batch / C3 事件接入 Playwright。

验收总门禁：`python tools/metrics_report.py --week` 在空数据目录能优雅输出"本周无事件"
而非报错；事件写入路径在 Windows CI 通过；文档（README 开发节）包含周报模板链接。

## 7. 明确不做（Non-Goals）

- 不做远程上报：一切度量留在本机，`data/metrics/` 永不自动外发；
- 不做实时仪表盘：周报粒度足够；单会话排障用 run events，不需要新面板；
- 不做 A/B 框架：单用户本地产品没有分流语义，提示词/规则对比用路径 5 的双轨一致性
  评测承担；
- 不引入 SQLite 之外的存储：JSONL 按日滚动 + 采样已满足单机规模。
