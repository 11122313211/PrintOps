# HTTP 请求预算与模型状态隔离

当前实现使用 Python 标准库；入口为 `request_runtime.py`、`server.py`、`llm_adapter.py` 和 `storage_sqlite.py`。这是本地运行时能力，不是实际供应商或模型 provider 验收结论。

## 一次请求，一个总时限

默认 `PRINTOPS_REQUEST_TIMEOUT=30` 秒。HTTP handler 在读取请求行之前建立 monotonic 截止时间，后续请求头、请求体、会话锁、配置锁、SQLite 操作、模型工具轮次、HTTP 重试、native/JSON 回退及成功响应都消费同一剩余预算，不逐轮重新获得 30 秒。

请求读取另有定时器在截止时中断读端，因此每隔一小段时间发送一个字节也无法无限刷新 socket 超时。模型单次规划还保留自身较短预算，取它与 HTTP 剩余时间的较小值。SQLite 每条语句的 busy_timeout 按剩余时间收缩，并在提交前检查；内核 `_save()` 同样拒绝截止后的提交。已经在截止前成功提交的操作不会被伪装成回滚。

总时限到期时，已能解析的 API 请求尝试返回 HTTP 408 / `REQUEST_DEADLINE`，提示先核对订单状态再重试；只给错误响应最多 0.1 秒写出窗口。连完整请求头都没有发送的客户端也可能只看到连接关闭。前端不能把超时直接解释成“服务器什么都没做”，应读取当前版本/操作记录后再决定重试，沿用幂等操作标识。

设置 `PRINTOPS_REQUEST_TIMEOUT` 为非正数会沿用兼容的 HTTP 总预算禁用行为，不建议在需要慢客户端保护的部署中关闭。直接调用 Agent/MCP 不会自动获得 HTTP 上下文；模型适配器自己的单次规划/探测预算仍有效，其他宿主需要用 `deadline_scope()` 提供总预算。任意企业自定义存储和工具应自行遵守同一上下文；不能宣称 Python 可强制中断任意用户代码或系统磁盘故障。

## 声明式路由预算与探测快速失败

借鉴 dsh 的 clampTimeout 语义，声明了自身有界网络工作的路由可以获得单独封顶的预算：`/api/model/test` 在解析出请求体后，把总预算提升到"一次有界地址校验 + 连通预探测 + 三跳并发能力探测（单次往返） + 响应写出"（路由声明 40 秒，封顶 120 秒），不再让合法的慢端点测试在全局 30 秒截止线上被误伤成通用 408。显式配置更小 handler 预算的部署与测试保持原值，路由不会放宽它。

保存设置时的主机名校验限制在 6 秒：DNS 无响应返回 504 / `ADDRESS_VALIDATION_TIMEOUT`（前端提示检查 DNS/代理），而不是吃掉整个请求预算后变成含义模糊的超时。

能力探测参照 cc-switch 分层执行：先在不携带 API Key 的前提下发一个不读响应体的 header-only GET 证明端点连通（任何 HTTP 状态都算活着，只有网络级失败判定不可达，连接预算 2.5 秒），chat 跳同时并行发出；连通确认后 JSON 与原生工具跳立即扇出，三跳在**同一次往返**内完成。预探测或任一跳先给出网络性失败（连接超时、拒绝、DNS、TLS）或鉴权失败（HTTP 401/403）时当场终止并给出根因文案。单跳预算不低于 6 秒、不高于 15 秒并尊重 `PRINTOPS_LLM_TIMEOUT`，慢推理模型不再被硬顶误判为不可达。每跳耗时写入 `probeTimings`。

早期版本还会串行补发一次"工具结果续接"生成请求验证 `role: tool` 回合。实测该跳在推理模型上需要 2–9 秒（思考时长与输出长度无关，`max_tokens=1` 也不能缩短），成为探测总耗时的主要来源；同时它按模型是否回显标记判定，模型改写成总结即被误判为"续接失败"。该契约已由 Agent 运行期覆盖——规划器在 native 回合被 400/404/405/422 拒绝时自动改用 JSON 协议重试——因此探测不再为它多花一次往返与配额。真实端点实测：串行四跳 5.8 秒 → 单次往返三跳 2.8–3.1 秒。

"不可达 / 服务不可用"的失败结论在 `PRINTOPS_MODEL_TEST_FAILURE_CACHE_SECONDS`（默认 15 秒，0 关闭）内复用，连点不再重复消耗配额：缓存键是接口 URL 与模型的 SHA-256 指纹，不含 API Key；成功结论与鉴权结论一律不缓存，设置页标注"复用 N 秒前的判定"，下一次点击自动强制重测。同时在飞的探测上限 2 个，等待 2 秒仍拿不到槽位返回 429 / `MODEL_TEST_BUSY`。浏览器在探测进行中关闭弹窗时，Windows 以 `ConnectionAbortedError`（10053）报告这次中断写，服务端按正常流量吞掉，不再落进通用处理器记成 500。

`PRINTOPS_LLM_TIMEOUT`（默认 20 秒，5–120 秒封顶）为慢推理模型提供更大的单次规划预算；调高它时必须同步调高 `PRINTOPS_REQUEST_TIMEOUT`，因为规划预算取两者较小值，模型请求永远不会活过所在 HTTP 请求。

## 模型配置快照

请求在短配置锁内复制 URL、模型、Key、超时等配置，之后只使用自己的 planner。该请求的工具续轮共用此实例，保留自己的协议状态；其他请求、配置变更和能力探测不会覆盖其 `last_error` / `last_protocol`。设置页反映保存配置，请求结果反映该次诊断。配置验证和模型网络调用在配置锁外执行；验证通过后才发布新配置。

## 无法硬取消的标准库 I/O

Python 无法安全强制终止阻塞中的系统 DNS 解析，urllib 在收到完整响应头之前也不总能暴露可关闭的 socket。为防止此类调用占住 HTTP handler，外部读取在最多 **8 个 daemon I/O worker** 内执行；等待 worker 容量也计算在请求预算内。保存设置时的地址校验属于控制面操作，单独使用 2 个槽位（`CONTROL_SLOTS`）：一次卡住的模型探测占满 8 个模型槽位时，修复该接口的"保存"仍然能执行，而不是排队 6 秒后被误报成 DNS 超时。

超时调用方立即停止等待。迟到的响应不被解析成订单修改，不更新请求诊断；worker 在其 I/O 退出后关闭资源并释放槽位。响应体大小有上限（规划 2 MiB、能力探测 256 KiB），可读取的响应体按剩余时间设置 socket 超时。仍未结束的系统 I/O 会继续占用一个受限槽位，因此这不是操作系统级硬取消；持续异常时模型请求可能因容量不足超时，健康接口及规则路径仍独立。业务状态更新不放到这些 worker 中运行。

## 回归证据

`tests/test_request_deadlines.py` 使用本地 socket、临时 SQLite 和合成模型响应，覆盖：

- 逐字节请求头/体在总时限内被终止，连接槽释放。
- 会话锁等待到期不修改订单；SQLite 写锁竞争消耗剩余预算且原订单不变。
- 连续规划轮次共用预算，已超时的后续轮次不再发请求，迟到结果被丢弃。
- 外部读取容量有上限，锁等待可超时，截止后内核保存被拒绝。
- 配置变更不改变在途快照，错误不跨请求串扰，能力探测不阻塞设置读取。

`tests/test_llm_probe_budget.py` 用假网关与注入异常覆盖同一套预算：预探测的超时/HTTP 应答/传输异常 fail-open 三类、三跳并发与首个根因早退、单跳预算上下界、失败结论复用与 `force` 重测、缓存不含 Key、并发上限 429、慢端点不被全局截止线误伤；Windows 中断写由 `tests/test_runtime_hardening.py` 的 `ClientAbortTest` 覆盖。

这些是合成运行时证据，不代替真实 provider、真实 dsh、真人可用性或所有部署环境验证。
