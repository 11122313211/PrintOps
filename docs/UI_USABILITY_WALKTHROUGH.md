## 开场与计时

主持人逐字读：**“我们在测试这个产品。请按你自己的理解完成接下来的短任务；不会先演示操作。你可以提出问题，也可以随时停止。任务中的订单都是测试资料。”** 不介绍区域分工、按钮名称或位置。

每项先让参与者读完任务卡。参与者表示准备好后，主持人说“可以开始”，立即记 `start_at`；不要等到首次点击才开始。阅读与任务间恢复环境不计时，思考、滚动、等待、走错、求助均计时，不暂停。

记录首次点击或键盘动作的目标和相对秒数；鼠标可补截图坐标。另记 `entry_found_elapsed_s` 和完成总秒数，两者不能混成同一指标。每项最长 **120 秒**：达成下表结束条件即停表，或在超时、参与者放弃、环境中断时停表并保留原因。超时后继续探索可另记，不能回填为按时完成。

## 求助与错误怎样记

主持人不提示区域、按钮名或操作顺序，不代操作。只可原样重读任务、提供准备表已有业务事实，并记录这类澄清。参与者明确要求操作帮助时可协助以继续观察，但从首次操作提示起，该项不再算“无需提示完成”。

| 事件 | 记录方法 |
| --- | --- |
| 求助 | 记发生秒数与原话，即使未提供帮助也保留。业务事实澄清另记，不算操作提示。 |
| 操作提示 | 记主持人原话/指向/代操作及秒数；透露按钮名、位置或下一步都算提示。`operation_help_count` 至少为 1，独立成功填“否”。 |
| 误入 | 实际进入与任务无关的订单、页面或菜单，后又返回/求助，每次进入算 1 次；记录目的地。普通阅读、滚动和键盘经过控件不自动算误入。 |
| 漏找 | 到 120 秒仍未找到该项所需入口，`entry_missed` 填“是”；找到耗时保持空白，不填 120 冒充找到。 |
| 误确认 | 分开记录误触尝试与真实生效次数，保存订单/确认/revision 证据。被禁用或拦截也不能抹掉尝试记录；原本要求取消却真的新建，也属意外生效。 |
| 误导出 | 未被任务要求却实际产生下载，记录文件与时间；只进入预览不算下载。 |
| 丢输入 | 记录预置/用户已写未发原文与返回后内容；非用户主动清空的消失、截断、被其他订单文字替换均计入。主动删除要有操作或原话依据。 |
| 环境中断 | 记故障、发生时间和实际界面，结束本次任务并保留“环境中断”。重做另起记录，不覆盖原结果，也不记为成功。 |

出现误确认、误导出或丢输入时，先保存证据；不要引导修好后把首次任务记为通过。结束后再恢复合成环境。

## 空表填写与 4/5 判定

使用 [observations-template.csv](../reports/ui-position-tuning/usability/observations-template.csv)。30 行只预填计划槽位、任务、顺序及“待执行”状态，实际参与者编号、时间、次数、结果全部为空。执行时复制一份为新轮次文件，保留模板；执行后再将 `execution_status` 标为“已执行”或“中断”。

- 时间统一记录含日期与时区的时间戳；相对耗时以秒记录。次数仅在实际观察后填 0 或正整数，未执行不能填 0。
- `help_requested_count` 只统计操作求助；任务事实澄清写入 `event_log`。首次动作、求助、误入等事件保留相对秒数、原话和实际目标，不只填汇总次数。
- `outcome` 填“完成 / 获助完成 / 未完成 / 超时 / 放弃 / 环境中断 / 未执行”。`independent_success` 只有在 120 秒内达成全部停表条件、没有操作提示且证据完整时填“是”，其余已执行项填“否”。单纯请求帮助但未获得提示，不自动失去独立资格。
- 每个任务分别以 5 名不同首次用户为固定分母，至少 **4/5 无需提示完成**。失败、获助、放弃和超时不得移出分母；招募不足、任务未执行或缺证据时记“证据不足”，不宣称达到阈值。不挑掉失败者补满五名。
- 整轮还要求：关键入口漏找、误确认尝试与生效、误导出、非主动丢输入均为 **0**。任一发生则护栏未通过，即使某项达到 4/5 仍不能判整轮通过。
