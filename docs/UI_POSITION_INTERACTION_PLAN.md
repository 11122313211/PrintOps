进一步只读检查在 Chromium、WebKit 各 8 条路径中复现两项尚待处理的问题：点击遮罩关闭左栏后焦点掉到 BODY；跨断点隐藏当前栏位后焦点丢失。现有可见焦点和原生弹窗的控制组正常。详见[修复前独立审查](../reports/ui-position-tuning/focus-dismiss-review.md)，这些不能写成已经修好。

依据为当前 `index.html`、`styles.css`、`app.js`、`journey.js` 和最近一次导航移除的实际截图。起点是已撤回大改后的当前页面，保留刚完成的顶部阶段导航移除。这次目标是让入口好找、位置稳定、对话好用，不重新设计订单流程。

## 1. 范围与交付边界

保持现有暖纸色、品牌红、字体、按钮语言、三栏结构、栏宽与开关偏好。以移动现有节点、调整局部间距和必要的焦点处理为主，不引入框架、布局控制器或新的工作阶段。

保留消息发送、追问、方案生成与选择、参数编辑与候选确认、本地生成与确认、文件检查、导出、历史和归档的原有条件及请求。Agent、后端接口、订单状态、存储和计价均不在本计划修改范围内。字段编辑器合并、删除业务能力、默认关闭右栏和重做拖动控制器也不纳入。

本计划起草时只更新了文档。后续按小批实施位置调整，并依据实际回归修复了弹窗焦点、输入法回车与切单后控件状态恢复；没有更改后端、请求协议或订单确认规则。

## 2. 入口应放在哪里

“统一入口”指同一能力有明确的固定位置；上下文中的快捷操作可以保留，并复用同一原动作。不把所有操作塞进一个菜单，也不删除用来回到已有结果的入口。

| 区域 | 承担的事情 | 位置约定 |
| --- | --- | --- |
| 顶栏 | 全局识别、连接状态、应用设置 | 接口设置与高对比先保留现有位置，避免同时改动所有习惯。 |
| 左栏 | 新建、历史、常用规格、现有工具 | 新建靠近历史；已有进度和工具保留。 |
| 中间 | 阅读对话、输入、上传、发送 | 不恢复顶部阶段导航；左右栏开关分别靠近对应边缘。 |
| 右栏 | 当前订单参数、方案/交接入口、供应商信息 | 方案与交接入口前移；平台选择靠近供应商状态。 |
| 方案/交接页面 | 查看原有内容、执行原有动作 | 继续使用现有页面与“返回对话”，不搬移业务组件。 |

| 编号 | 当前问题 | 具体调整 | 验收 |
| --- | --- | --- | --- |
| A1 | 右栏“查看工艺方案 / 查看交接资料”位于参数与待处理清单之后，长订单需要滚动查找。 | 将 `.order-document-links` 整体移到“订单草稿”标题下、上传区之前；保留两个按钮与 `data-view`。 | 打开右栏即可找到；未选、已选方案和已确认订单都能再次查看；不自动生成、改选或导出。 |
| A2 | 左右栏开关并排挤在中间标题右侧，位置没有对应实际栏位。 | `#sidebar-toggle` 移至对话标题左侧；`#order-toggle` 留在最右侧。沿用现有图标、按钮尺寸和事件。 | 桌面及窄屏都能开关；标题不换行挤压；键盘顺序跟视觉顺序一致。 |

## 4. 第二批：让操作靠近它的对象

| 编号 | 当前问题 | 具体调整 | 实施注意与验收 |
| --- | --- | --- | --- |
| B1 | “新建订单”在全局顶栏，历史列表在左栏，两者距离远。 | 将唯一的 `#reset-order` 移到左栏历史标题上方；保留确认弹窗。 | 窄屏先展开左栏才能新建，记录这一步的发现成本。打开确认弹窗后，焦点必须在弹窗内；取消后返回触发入口，原订单不变。 |
| B2 | 目标平台在顶栏，供应商状态却在右栏，容易混淆应用设置与订单目标。 | 将 `.platform-control` 整体放到右栏 `.provider-status` 内、状态文字之前，继续清楚显示“目标平台”。 | 不自动选择或恢复另一平台；仅用户主动切换才走原 `/api/platform` 请求；归档及处理中禁用规则仍有效。 |

B1 的手机确认弹窗需要特别检查：当前左栏已有 Tab 焦点限制，搬入后可能与 dialog 抢焦点。若复现，只修这处展示交互，不重写新建订单逻辑。B2 的平台选择是订单修改，不作为“外观设置”隐藏进接口设置弹窗。

这批仍保留高对比、接口设置的位置。减少同时变化的入口，方便分辨体验改善来自哪里。

## 5. 第三批：通过使用观察，再决定对话区减法

这两项会影响首用理解与下一步发现，先作为可比较的候选，不跟前两批捆绑实施。

实施进展：C1 已因 390×667、390×568 下发送区被遮挡的实际证据落地，原示例与只填入行为保留；C2 仍未实施。短横屏以可滚动到达输入与发送为验收，不要求所有内容固定在一屏。

| 编号 | 候选调整 | 必须保留 | 如何判断 |
| --- | --- | --- | --- |
| C1 | 将首屏用途三卡折叠为一行“查看输入示例”，主动展开后仍显示原示例。 | 原 `data-example` 内容、只填输入不自动发送的行为；真正的动态追问与工艺方案不受影响。 | 新用户是否能直接开始输入；需要示例的人能否找到；窄屏输入区是否更完整。 |
| C2 | 将底部 `.task-bar` 缩为输入框上方的轻提示行，保留当前动作；窄屏允许自然两行。 | `next-task-title/description/action` 与原动态回调；所有生成、确认、导出条件不变。 | 聊天可见面积是否增加；用户是否仍能找到下一步；长提示是否推走输入框。 |

C2 不直接搬到右栏：右栏关闭或手机切到对话时，下一步会更难发现，且动态回调与手机视图联动需要额外改动。先比较轻提示样式，收益不足则维持现状。

## 6. 视觉与工程约束

- 复用现有颜色、字号、圆角与间距令牌；不全量重写样式，不顺手修改其余卡片。
- 两侧对应按钮使用同一尺寸、焦点和悬停规范；高频操作的触控目标至少 44 CSS px。
- 移动真实节点、保留唯一 ID 与事件，不复制输入框、平台下拉、生成按钮或文件控件。
- 输入区保留唯一上传入口；右侧 PDF 拖放区是与文件关联的快捷入口，两者仍调用原处理程序，不为了“唯一”删掉拖放能力。
- `journey.init()` 会把估算/推荐移到比较页，把生成/确认/复制/导出移到交接页。实施必须核对初始化后的真实 DOM，不能只看 HTML 源位置。
- 保留已有 `data-view` 返回处理。位置变化不增加业务请求，也不通过改变禁用条件让按钮看起来可用。
- 每批建立当前工作区快照，只对该批实际文件生成回退差异。已有未提交的业务改造和本地订单数据不纳入回退。

## 7. 测试顺序与判定

**先校准测试基线（已完成）。** 起草时，`tests/journey.fixture.mjs`、部分 smoke 测试和截图脚本仍依赖已撤销的 `#phase-order`、`#open-options`、`#open-handoff`、`#sidebar-more` 等节点，部分断言要求当前仍存在的引导卡与任务条全部消失。已让回归测试匹配当前真实界面及既有行为，取消撤回设计的断言，保留字段、版本、产品归属、归档与导出保证。不能为满足旧测试重新引入被撤回的布局。完整结果见验收记录；历史失败保留在基线校准报告中。

**再记录当前基线，逐批对比。** 使用隔离 SQLite 和人工测试订单；不往现有业务订单发送试验内容。当前已有的四组导航检查只覆盖最近删除阶段栏的变更，不能作为本计划已验收的证据。

| 场景 | 操作与判定 |
| --- | --- |
| 首次进入/继续聊天 | 不先选工作阶段即可输入；发送仍只触发一次原请求；中文输入法组词、长输入、上传入口正常。 |
| 方案往返 | 从固定入口查看，返回后保留未发输入；已选方案还能再次查看和改选；仅查看不改变 revision。 |
| 交接往返 | 已生成/已确认订单可纯查看；打开预览不隐式确认或下载；导出仍核对当前版本。 |
| 新建与历史 | 取消新建后订单、对话不变；确认新建后旧单仍可恢复；窄屏弹窗焦点正确。 |
| 平台与文件 | 切换平台只执行原操作；两处文件入口关联同一当前产品；检查归档只读及处理中禁用。 |
| 排版与键盘 | Chromium/WebKit，390/768/1280/1440px；长中文/文件名，无页面横向溢出；输入框及发送可见；Tab 顺序、Escape、焦点返回正确。 |
| 真实设备 | 单独检查实际手机软键盘与真实 200% 浏览器缩放；桌面窄视口不能替代这两项。 |

自动化记录 console 错误、意外请求、revision、产品归属和草稿，不只截静态图片。单纯位置变化重点运行相关浏览器回归；若意外涉及后端，先拆出变更，不扩大本计划范围来消化它。

**使用体验观察：** 建议安排 5 名未参与开发的人，各完成“继续聊天、找回旧单、新建后取消、查看并返回方案、查看交接、找到平台设置”六个短任务。记录首次点击位置、找到入口耗时、走错次数、是否需要提示。建议试验目标为每项至少 4/5 人无需提示完成，关键按钮漏找、误确认、误导出和输入丢失为 0。该阈值是这次小范围走查目标，尚无真人结果，不等同于原有完整订单北极星验收。

## 8. 每批 review 和交付

每批交付：同订单同视口前后截图、实际修改文件及差异、通过/失败的交互记录、独立 review 结果。review 重点是入口可达、位置一致、键盘与手机焦点、误触，以及是否越界修改原逻辑。

建议实施顺序为 **A1/A2 → 验证 → B1/B2 → 验证 → 根据观察决定 C1/C2**。发现位置收益不明显时回退该小批，不继续扩大重构。最终不以“界面更漂亮”作为完成标准，而以入口更好找、对话占用更少、原有操作仍完整为依据。

## 9. 下一阶段可执行安排

### 9.1 固定入口分工，先让用户知道去哪里

### 9.3 可比较的位置方案，按观察结果选用

| 观察到的现象 | 局部方案 | 保留与取舍判定 |
| --- | --- | --- |
| 多人先找旧单/新建，却被左栏进度信息挡住视线 | 将现有历史区整体放到进度区之前，让“新建 + 历史”靠近左栏顶部；进度仍保留。 | 只移动真实节点，不复制新建按钮或改变默认展开偏好。复验相同任务；若旧用户找进度更困难且入口发现没有改善，撤回该组。 |
| 右栏“查看工艺方案 / 查看交接资料”文字太挤、漏点 | 在标题下保留原位置，调整两个现有按钮的间距、对齐和点击范围；窄栏允许自然换行。 | 使用原按钮和 `data-view`，不做新的入口卡片或增加一排阶段选择。以漏找、误触和空间占用比较，不能仅凭截图判断。 |
| 手机两个侧栏图标被误认 | 先比较现有按钮的短文字标签和局部留白；在最窄视口核对标题是否被挤压。 | 沿用现有开关和无障碍名称，不新增入口。没有误认记录时维持当前样式。 |
| 输入区仍被底部下一步任务条挤占 | 只试 C2：将原任务条排成输入框上方的轻提示行，长文字可换行；减少边框和上下留白。 | 原动态动作、禁用和确认语义保留。对比“能否找到下一步”及发送可达性；两者有一项变差就撤回，不删除动作或搬到手机不可见的右栏。 |

左右栏统一的是同级标题、间距令牌、按钮高度、焦点和分隔规范；保留左栏导航、右栏编辑的各自布局。复用已有 `--space-*`、字号、颜色及圆角，不另起一套设计系统；高频触控目标至少 44 CSS px。尺寸展示继续使用 mm，原有规格含义不因排版省略。

### 9.4 测试与 review 怎么交付

排版覆盖 320、390、768、1280、1440 px，断点补查 1050/1051 px；补充 390×568 短屏、844×390 横屏、长中文、长文件名和多产品。没有页面横向溢出，输入和发送可到达，侧栏滚动不遮挡入口，视觉顺序与键盘顺序一致。短横屏允许滚动访问，不把所有内容硬压在一屏。

交互除六个任务外，保留归档只读、取消弹窗、方案改选后的原校验、已确认交接的纯查看、延迟响应期间切单等现有保护。查看/返回/收栏/缩放不得产生订单修改请求、意外确认或下载；明确发送、改平台、改字段等操作仅产生原有预期请求。核对订单 ID、revision、产品归属与未发原文，不能只看按钮是否可点。

开发实施负责小批位置/CSS及确有证据的局部焦点修复；独立 review 负责逐项核对范围、实际初始化后的 DOM、浏览器证据与误触路径，发现问题写明复现步骤，不同时扩写另一套布局。每批交付一张前后对照、修改清单、通过/失败/未执行记录，以及仅覆盖本批的可撤回差异。整个 Git 工作区不作重置。

验收命令使用现有配置，例如：

```sh
PRINTOPS_FOCUS_RUN=next-ui-review npx playwright test --config tests/ui_focus.config.mjs
PRINTOPS_TEST_BROWSER=webkit PRINTOPS_FOCUS_RUN=next-ui-review npx playwright test --config tests/ui_focus.config.mjs
```

报告目录按批次保留；必要时增加相关位置或 journey 回归，不重复把历史通过记录计成当前源码的完整验证。当前 native Safari 最终版本 200% 复验与测试标签清理仍因锁屏待完成，见 [UI_FOCUS_REVIEW](UI_FOCUS_REVIEW.md)。

这阶段以“入口更容易找到、对话不被挤占、原有操作可靠”为交付依据。平台授权、至少 20 条真实脱敏订单及 8 人完整订单北极星验收保持原门槛，不以 UI 小样本或合成回归替代。
