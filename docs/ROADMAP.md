# PrintOps 持续目标

## 北极星目标

让首次使用的非印刷专业用户，在 10 分钟内独立完成一份规格正确、关键参数已核对、依据可追溯、可供供应商复核的本地交接单。

计时从首条有效需求开始，包含澄清、等待、修改、确认和导出；完成要求当前版本通过必要校验，关键生产参数完成核对，用户明确确认，并实际打开与该版本一致的导出文件。“字段填满”“可生成”“已确认”“文件已检查”“供应商已接收”分别表达。没有文件时写明待交付，不声称可直接生产。

主指标为“600 秒内独立完成且通过独立内容复核的主任务数 / 所有已开始的主任务数”，失败、放弃和超时保留在分母。首轮 8 人各做一个指定任务：名片 3 人、单页 3 人、标准宣传册 2 人；目标至少 7/8 合格完成，关键数量/尺寸错误、串项及过期确认沿用为 0，全部参与者理解估算非报价且订单尚未发送。真人结果目前未执行；固定任务与空白评分见 [USER_WALKTHROUGH](USER_WALKTHROUGH.md)，不能替代真实语料门槛。

产品闭环按实际准备状态推进，允许返回修正：

```text
用途与需求 -> 参数补全与核对 -> 工艺比较 -> 本地交接复核 -> 明确确认 -> 导出并检查
                   文件：已提供则记录基础检查；未提供则明确待交付
                   价格/供应商能力/交期：分别列出示例与待核实边界
```

模型负责理解和解释，规则负责约束，工具负责执行，人负责核对和确认。当前导出不会自动发送供应商。

### v0.8.2 会话与多产品基座

- 多产品订单保存为带稳定 `itemId` 的独立 `items`。
- 每个产品项都有独立的基础字段、品类参数、信息度和缺失项。
- 通过“处理第 N 项”或 API 的 `itemIndex` 更新指定产品项，避免参数串项。
- 每个产品项可以独立校验、推荐工艺、选择方案、估价和准备待确认询价。
- 所有产品项分别完成并选择方案后，才能生成整体交接摘要；修改产品项会自动使旧方案和整体草稿失效。
- API 路由分发已抽为无网络副作用的契约边界，接口测试覆盖会话、`itemIndex`、错误路由和整体生成阻断。
- 询价请求持久化到会话，使用订单、平台和 `itemId` 生成稳定幂等键；重复请求复用原请求，不重复生成。
- 新增询价状态查询和取消 API；订单字段、文件或平台变化会将待确认询价标记为 `stale`，重启后仍可恢复。

- 右侧订单区显示询价状态、请求编号、刷新和取消操作；新增询价生命周期与 API 契约回归测试。
- 品类参数、尺寸语义、风险边界和供应商能力档案带有知识版本与来源元数据；`/api/products` 和订单响应可追溯当前依据。
- 尺寸语义已在订单模型、迁移逻辑、多产品编辑和导出中统一；模型或旧客户端写入的尺寸别名会被归一化。

这仍不是完整的多产品下单：当前请求闭环只在本地运行，供应商真实提交、报价回写和浏览器端多文件批量校验仍待完成。

## 系统优化路线图（2026-09 前端统一走查发现）

> 十条优化路径的完整方案、任务卡与测试矩阵见[后续完善开发计划书](DEVELOPMENT_PLAN.md)（总纲 + docs/plan/ 十篇路径 + 四个附录）。

以下为本轮 UI 统一走查时确认的后端议题，按优先级排队；**v0.11.0 已消化 P0 全部与部分 P1/P2**（标 ✅），其余继续排队。

### P0 安全
- ✅ 本地 API 无鉴权与限流：v0.11.0 起启动时生成本地 token 注入页面，除 `/api/health` 外全部接口要求 `X-PrintOps-Token`；带 Origin 的跨来源请求返回 403。限流仍未做，作为后续项。
- ✅ `/api/settings` 保存的 API Key 以明文 JSON 落盘：设置面板与 `/api/settings` 响应已加 `keyStorageWarning` 明文风险提醒；改用系统凭据库（Windows 凭据管理器 / keyring）仍是后续增强（依赖零安装的前提下需评估方案）。
- ✅ 静态服务直接暴露根目录：静态路由白名单已生效（仅 /、/index.html、/app.js、/markdown.js、/workbench.js、/styles.css；API 单独鉴权路由），`/.git`、源码与数据文件一律 404。
- ✅ LLM URL 由用户任意填写存在 SSRF 面：配置时校验主机，拒绝环回/私有/CGNAT/保留/链路本地地址（含解析后指向内网的域名）；无法解析的主机名放行（请求时自然失败）。剩余风险：配置时校验与实际请求之间理论上存在 DNS 重绑定窗口，对单机工具可接受。

### P1 可靠性
- ✅ SQLite 无 WAL/`busy_timeout`：已开启 WAL 并设置 5s 超时；损坏会话自动隔离恢复（备份到 `data/corrupted/`）。
- ✅ HTTP 请求使用独立 planner 配置快照，`last_error` / `last_protocol` 不跨请求共享；`LLM_LOCK` 仅用于配置读写与快照，模型能力探测不再持锁等待网络。
- ✅ HTTP 总时限从请求行读取开始，慢头/慢体、会话和配置锁、SQLite 锁等待、模型所有轮次/重试/协议回退共用剩余 monotonic budget。超时禁止后续保存、丢弃迟到模型结果。默认 30 秒，可配置；标准库不可取消 I/O 的线程上限及边界见 [RUNTIME_BUDGET](RUNTIME_BUDGET.md)。
- 模型结果当前仍以整段响应展示，未实现 token 流式反馈；可以继续按真人等待体验决定是否增加流式展示。
- 重试策略形同虚设：仅 2 次尝试、80ms 退避，且 5xx 与网络错误重试后无抖动；按错误类别设置指数退避。
- 存储保留策略：当前已有快照/事件/消息/报价/审计分表、归档与导出，保留完整历史；仍需按业务要求设计容量监控、备份和保留期，不得直接淘汰尚需追溯的审计记录。

### P2 工程化
- ✅ `_update_order`/`_update_item` 双份近似逻辑与常量重复：已合并为 `_apply_patch` 统一补丁引擎，死常量与无用 import 已清理。
- 关键词 NLU 与 LLM 双轨行为差异需要在评测集固化（同一句话两种模式结果一致性断言）。
- `/api/chat` 文本无长度上限（仅整体 1MB body 限制），应加单条消息长度校验。
- 无打包/发布产物：依赖零安装是特色，但缺少 `pipx`/zipapp 交付与版本清单。

## v1.4+ 顺延项（规划）

- **计价引擎 schema 3.0**：拼版大纸、批次开机费、设备阶梯，以及纸杯/信封等三维品类驱动；当前纸杯、联单、PVC 展板三条例外 blocked 的原因都引用该规划，落地后随新 rate card 标定解禁。

- **供应商 sandbox/live 接入**：当前无授权，沿用下述原边界。
- **真实语料与真人走查门槛**：保持组织性阻断，不视为候选版阻塞项；发布检查按预期失败，见 [RELEASE_CHECKLIST](RELEASE_CHECKLIST.md)。

### 供应商授权接入与真实价格校准

- 在现有 `SupplierConnector` 协议上实现授权供应商的 sandbox transport，取得官方字段枚举、产品编码、单位、限流、报价有效期、回调与取消规则。

- 有授权的脱敏报价可由离线 CSV 生成未发布统计草稿；人工复核税费、运输、地区、尺寸、精确数量和工艺口径后，另行发布新的 rate card。现有示例参数不代表市场价。
- Postgres/企业存储通过可信注册扩展，须通过与 SQLite 相同的 CAS、事务、迁移和导出契约测试。
