# PrintOps 印刷订单智能体 MVP

这是一个轻量的印刷订单 Agent 原型，验证“自然语言需求 → 记忆订单 → 调用品类知识 → 工艺方案 → 订单草稿”的核心流程。

## 运行

在当前目录执行：

```bash
python3 server.py
```

然后打开 <http://localhost:4173>。

### Mac / Linux

也可以直接执行项目里的启动脚本：

```bash
./start_mac.sh
```

首次使用时如果脚本没有执行权限，可运行一次 `chmod +x start_mac.sh`。

### Windows

双击 `start_windows.bat`，或在 PowerShell 中执行：

```powershell
.\start_windows.ps1
```

项目只使用 Python 标准库，不需要 `pip install`。Windows 建议安装 Python 3.10 或更高版本，并勾选“Add Python to PATH”。

### 端口

默认端口是 `4173`。端口被占用时，Mac/Linux 使用 `PRINTOPS_PORT=4174 ./start_mac.sh`；PowerShell 使用 `$env:PRINTOPS_PORT=4174; .\start_windows.ps1`。

### 脱机排查

如果页面显示“无法访问此站点”或“脱机”，通常是本地服务没有运行。重新打开终端，进入本目录后执行上面的启动命令，并保持终端窗口运行；再刷新页面即可。

可以用下面的地址快速确认服务状态：

```text
http://localhost:4173/api/health
```

看到 `{"ok": true}` 表示服务正常。若启动时提示端口 `4173` 已被占用，说明已有一个服务在运行，先确认它是否就是本项目；需要并行启动时可执行 `PRINTOPS_PORT=4174 python3 server.py`，然后打开对应端口。模型接口临时超时不会导致页面脱机，Agent 会回退到规则模式，并在界面显示回退状态。

## MVP 范围

- 对话式收集通用订单字段，并按品类补充差异化参数（折页、联单、标签、包装盒、手提袋、纸杯、喷画/PVC 等）
- 内置盛大印刷公开产品导航启发的品类目录：别名、分类、关键参数、必问项、常见风险和推荐方向
- 支持“数量改为 1200 份”“不要覆膜”等订单修改，并自动作废旧方案
- 根据用途、预算、交期和产品类型生成经济、平衡、质感三种可解释工艺方案
- 可解释哑粉纸/铜版纸、出血、覆膜、颜色和装订等常见印刷概念
- 支持 PDF 文件类型与大小的前端预检入口
- 生成、复制标准化订单草稿
- 展示需求收集、方案选择、订单确认三个状态
- SQLite 保存会话记忆，刷新或重启后可继续订单
- UI 可配置 OpenAI 兼容 API URL、模型名和可选 Key；留空时继续使用规则 Agent，Key 只保存于本机服务端
- 模型模式会携带最近对话上下文，兼容裸 JSON、Markdown JSON、普通文本及常见 Responses 返回结构；模型异常会显示回退状态，不会让聊天接口返回空响应
- 显示 Agent 当前调用的工具、信息度和下一步动作
- 使用统一平台注册表，可扩展盛大印刷及其他印刷平台

## 品类参数模型

`product_knowledge.py` 把产品目录与 Agent 主循环分开维护。所有订单仍共享数量、尺寸、纸张、颜色和交期等基础字段；品类差异放在 `order.productSpecs` 中，避免用一张通用表误导非专业用户：

| 品类 | 需要优先确认的参数 |
| --- | --- |
| 画册/宣传册 | 页数、装订、封面用纸 |
| 单页/折页 | 折法（折页）、展开尺寸、出血 |
| 名片 | 卡纸克重、单双面、圆角/专色 |
| 联单 | 二联/三联、编号、装订方式 |
| 信封封套 | 成品尺寸、开口方向、糊口/刀模 |
| 标签/不干胶 | 面材、形状/刀模、胶水、使用环境 |
| 包装盒 | 长宽高、盒型结构、刀模、纸板与后道 |
| 手提袋 | 长宽侧宽、袋体材料、提手、承重 |
| 纸杯 | 容量、杯身材料、内淋膜、食品接触合规 |
| PVC 卡/吊牌 | 卡型、厚度、芯片；或挂孔、穿绳、承重 |
| 海报/喷画/PVC 板 | 展示尺寸、介质/板厚、室内外、安装加工 |

官网当前公开导航包括：名片/卡片、单张、标签/不干胶、书籍画册、广告物料、包装周边、办公用品、家居日常、动漫文创、季节产品、现货/样品。本 MVP 先覆盖前七类的高频产品，目录来自 [盛大印刷官网]（https://www.sd2000.com/）公开产品导航与页面信息，用于订单前置分流，不代表任何平台的实时报价或生产能力。供应商接入时应再维护一份能力/字段映射表。

当前版本使用轻量规则感知，不需要 API Key。点击界面右上角“接口设置”可填写 OpenAI 兼容 API URL、模型名和可选 Key；设置保存于本机 `data/llm_config.json`（权限 `600`），静态服务禁止访问该目录，接口响应也不会返回 Key。留空 URL 与模型名即可继续使用规则模式。`llm_adapter.py` 提供可选的 OpenAI 兼容模型适配器：模型可以返回结构化字段补丁和白名单工具名；调用失败会自动回退规则模式。当前不包含真实报价、专业印前软件级检查和官网自动提交；正式提交前仍需要人工确认。

## Git 与版本

项目按可运行里程碑使用 Git 管理。当前验收版本为 `v0.1.0`，详细记录见 [CHANGELOG.md](CHANGELOG.md)。源码、知识库和前端会进入版本库；`data/` 下的会话数据库、日志和模型配置被 `.gitignore` 排除，API Key 不会随 Git 提交。

克隆后可用下面的命令启动：

```bash
git clone <仓库地址>
cd print-order-agent-mvp
python3 server.py
```

推荐后续按 `v0.2.0`（新增功能）、`v0.1.1`（问题修复）的方式打标签。Mac 和 Windows 共用同一套 Python/HTML/CSS/JS 源码，只使用各自的启动脚本，订单逻辑和界面不分叉。

## API

`POST /api/session` 新建或恢复会话；`POST /api/chat` 对话补全订单；`POST /api/choose` 选择方案；`POST /api/generate` 生成订单草稿；`POST /api/preflight` 做基础文件预检；`POST /api/platform` 切换目标平台；`GET /api/platforms` 查看平台能力；`GET /api/products` 查看品类目录；`GET /api/tools` 查看工具；`POST /api/tools/call` 显式调用白名单工具；`GET/POST /api/settings` 查看或更新本地模型设置（不会返回 Key）；`POST /api/model/test` 测试当前或弹窗中填写的模型连接（不保存配置、不发送订单数据）。API 错误统一返回 `code`、`message` 和 `requestId`，响应头也带 `X-Request-ID`。
